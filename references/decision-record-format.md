# 决策记录格式

本格式适用于 `spec.md`、`design.md`、`tasks.md`、`evidence.md` 中提出的所有待确认或已回答问题。问题与记录放在当前阶段对应文档；其他文档若引用既有结论，应引用决策编号和当前结论，不要另造一个缺少选项的问句。

## 待确认问题

每题使用稳定编号，并记录问题原文、决策影响、所有选项原文、推荐项和理由、当前状态。聊天中的问题和文档里的问题必须一致。开放式问题没有预置选项时，写明原因。

## 已回答问题

收到回答后，将完整记录移至本阶段文档的“已确认事实”或“已确认决策”，包括：

- 稳定编号和问题原文。
- 决策影响。
- 当时向用户展示的全部选项原文，包含未选项、推荐标记和推荐理由。
- 用户答复原文；自由文本答案须原样保留。
- 解析后的当前结论及记录状态。
- 从待回答到确认的日期（可获取时）。

禁止只写“Q1：A”或仅保留选中项。问题答复后可从“待确认问题”清单移除，但完整记录不得删除。

## 答案更正

用户更正选择或补充规则时，不覆盖旧答案。在同一决策记录下追加新版本，分别保留每版的问题和选项快照、用户原答、结论和状态；旧版标记“已被修正”，最新用户确认的版本标记“当前生效”。如果问题文本或选项发生改变，保留旧版本并完整记录新版本，不复用旧选项内容。

格式示例：

```markdown
### REQ-Q1 窗口形式（当前生效：v2）

- 问题原文：工具使用哪种窗口形式？
- 决策影响：决定主界面和打开方式。
- v1 选项：
  - A：普通窗口（推荐），实现简单。
  - B：桌面悬浮窗。
- v1 用户答复原文：`A`
- v1 结论：普通窗口。
- v1 状态：已被修正。
- v2 选项：
  - A：普通窗口（推荐），实现简单。
  - B：桌面悬浮窗。
- v2 用户答复原文：`改成 B`
- v2 结论：桌面悬浮窗。
- v2 状态：当前生效。
```
